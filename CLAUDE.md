# RaffleGuru monorepo

Two apps, each with its own instructions — read the one relevant to what
you're touching:

- `apps/web/` — Next.js frontend. See [`apps/web/CLAUDE.md`](apps/web/CLAUDE.md)
  (design system rules) and [`apps/web/AGENTS.md`](apps/web/AGENTS.md)
  (Next.js version-specific conventions — auto-regenerated by `next dev`,
  don't hand-edit).
- `apps/api/` — Laravel API. See [`apps/api/CLAUDE.md`](apps/api/CLAUDE.md).

Cross-cutting docs live in [`docs/`](docs/):
[`docs/PRODUCTION_ARCHITECTURE.md`](docs/PRODUCTION_ARCHITECTURE.md) for
how the pieces fit together, [`docs/ROADMAP.md`](docs/ROADMAP.md) for what
gets built next, and [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md) for the
customer-facing walkthrough (what a customer can actually do today, page
by page) as opposed to the per-phase API references.

## Rules that apply everywhere

- This is a production system being built incrementally — don't add
  Competition/Ticket/Order/Payment/Draw/Winner domain logic without it
  being explicitly asked for; check `docs/ROADMAP.md` for what phase we're
  actually in.
- Docker/infra files (`infrastructure/`, `docker-compose*.yml`,
  `.github/workflows/`) affect both apps — read
  `docs/PRODUCTION_ARCHITECTURE.md` before changing them, and re-verify
  with `docker compose config` + `docker compose up --build` after.
- Never commit `.env` files. Each app has a matching `.env.example` —
  update the template alongside any new required variable.
